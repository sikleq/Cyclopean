# Cyclopean — Deadlock change history

## Старт сессии — прочитай это

**Язык общения:** отвечай пользователю на русском, отчёты — таблицей простым языком.

Cyclopean показывает, как менялась Deadlock: каждая сборка игры сравнивается с
предыдущей по файлам данных, результат склеивается с официальными патчноутами.
Всё, что есть в данных, но не в тексте Valve, помечается как **скрытое**.

Прочитай перед работой:
- `AGENTS.md` (этот файл) — источник правды и правила.
- `docs/architecture.md` — конвейер данных и сборка сайта.
- `docs/data-sources.md` — откуда что берётся (трекер, Steam News, форум, VPK).
- `docs/hero-stats-table.md` — колонки таблицы героев и их поля в файлах.

## Источник правды

- Данные игры: клон `SteamTracking/GameTracking-Deadlock` в `vendor/` (в git не
  входит). Каждый коммит трекера = одна сборка игры. Читаем только через
  `git show`, рабочее дерево трекера не трогаем.
- `data/` — сгенерированные JSON, **коммитятся** (сайт собирается из них в CI без
  трекера). Руками их не правят: правка = изменение генератора + тест.
- Ручные поправки (сопоставление строк патчноута, исключения) — только в
  `data/overrides/*.json`, поверх сгенерированного, с комментарием «почему».
- `build_site.py` — единственный вход сборки сайта. `dist/` не коммитится, его
  собирает и выкладывает CI (GitHub Pages).
- `site/styles.css` и `site/scripts.js` — единственный источник стилей и
  поведения. Все цвета — только токены `:root`; JS читает цвета из CSS-переменных,
  хардкод hex/rgba вне `:root` запрещён (в Sloppy это стоило сотен правок).

## Правила данных (уроки Sloppy)

1. **Данные сначала.** Нормализованный JSON — источник правды, страницы строятся
   чистыми функциями из него. Никакого рукописного DSL и парсинга готового HTML.
2. **Каждую ручную правку учить генератор** — правка + тест + «почему» в коде.
3. **Файлы игры авторитетнее вики и пересказов.** Сравниваем по смыслу
   (сущность → поле), никогда построчно: Valve переставляет записи, построчный
   diff сборки 6711 — 230 тыс. строк шума.
4. **Внутреннее имя ≠ игровое** (`hero_werewolf` = Silver, `hero_astro` =
   Holliday). Имена всегда из локализации **той же сборки**.
5. **Старые описания — только из истории локализации**, не выдумывать.
6. **Числа пишем как в игре:** метры = юниты / 39.37 (так же в таблице
   пользователя), проценты и секунды — с единицами из `m_eDisplayUnits`/суффикса.
7. **Направление (BUFF/NERF) — по значению, не по слову.** «Cooldown increased
   from 27 to 29» — NERF, потому что у кулдауна «меньше = лучше». Полярности
   полей — в `pipeline/semantics.py`, новые поля без полярности = CHANGED.
8. **Отсутствующую иконку не подменять молча**: allowlist с причиной или ошибка
   сборки. Иконки — только из VPK игры, никаких CDN-хотлинков и фан-арта.
9. **Живые проверки отдельно от деплоя**: сбой Steam API не должен ломать
   выкладку.

## Правила интерфейса (уроки Sloppy)

- Пиксельный стиль, но своя палитра: «патина и кость» (см. `site/styles.css`,
  блок токенов). Синий/янтарный — только со смыслом (команды Sapphire/Amber).
- Порядок строк внутри списка изменений: NEW → REWORK → BUFF → NERF → DEL → QoL →
  MISC → без тега. Сортирует сборка, не руками.
- Пустая ячейка таблицы — `—` (`.dash`).
- Сортировка колонок в 3 состояния: убыв → возр → нейтр.
- Липкие колонки: ширину пинить один раз при инициализации; разделители липких
  областей — overlay; `transform` на предке запирает `z-index` потомка.
- `:has()` на больших страницах запрещён (секунды пересчёта стилей) — факты
  пишутся классами при сборке. Сначала мерить, потом оптимизировать.
- Чипы-иконки без текста получают `data-tooltip`; других подсказок без просьбы
  не добавлять. Блёрбов-описаний на страницах нет.
- После правки CSS/JS пересобирать ВСЕ страницы (версия ассетов `?v=` = хэш).

## Процесс

- Код с обратными слэшами/регулярками писать только через Write/Edit, не через
  heredoc и не строками в shell.
- Временные файлы — только в scratchpad, не в корне репо.
- Документацию обновлять в том же изменении, что и код.
- Каждое видимое изменение сайта — запись в `data/changelog.json`.
- Перед push: `python -m pytest -q` и `python build_site.py`. После push —
  `gh run list --limit 3`, упавший CI чинить сразу.
- Репозиторий публичный: никаких локальных путей пользователя, токенов и следов
  других приватных проектов.
